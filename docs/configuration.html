Konfiguration

Alles in einer boxai.yaml.

Beispiel

Ein Fullstack-Workspace mit Kotlin-Backend und React-Frontend:

# Fullstack-Workspace mit Kotlin-Backend und React-Frontend.
# Start: boxai up --config examples/boxai.yaml
name: shop-feature-x
agent: claude
profiles: [kotlin-spring, react]
branch: feature/x
base: main
repos:
  - path: ../../shop-backend
  - path: ../../shop-frontend
    base: develop
  - url: git@gitlab.com:team/shared-lib.git
secrets: ./secrets.yaml
network:
  allow: ["nexus.firma.de:443"]

Start mit boxai up --config examples/boxai.yaml.

Felder

FeldBedeutung
nameName des Workspaces und der Sandbox
agentclaude, copilot oder (experimentell) antigravity
profilesStack-Profile, kombinierbar: kotlin-spring, react
branch / baseFeature-Branch der Worktrees und der Ausgangsbranch; base lässt sich pro Repo überschreiben
reposLokale Repos per path oder Remote-Repos per url
secretsPfad zu einer Secret-Datei
network.allowZusätzliche Host-Freigaben der Sandbox

Stack-Profile

Profile liefern Image-Wahl und Konfigurationsdateien. Zusätzlich erlaubt jede Sandbox github.com, api.github.com, gitlab.com und **.amazonaws.com.

Secrets

Die Secret-Datei verweist auf Quellen, nie auf eingebettete Werte. Referenzen in YAML sind ${env:NAME} und ${file:pfad}. Vorlage: boxai init erzeugt secrets.example.yaml.

Die Sandbox sieht nur einen Platzhalter, den der sbx-Proxy in Requests an die erlaubten hosts ersetzt. Deshalb sind hosts Pflicht, und boxai gibt jeden Secret-Host auch im Netzwerk frei.

Fallback secrets.mode: env

Für Tools, bei denen Platzhalter scheitern (etwa AWS-SigV4), übergibt boxai die echten Werte per Umgebungsvariable. Die Sandbox sieht dann den Klartext, und boxai warnt entsprechend.
