Configuration

Everything in one boxai.yaml.

Example

A full-stack workspace with a Kotlin backend and a React frontend:

# Full-stack workspace with a Kotlin backend and a React frontend.
# Start: boxai up --config examples/boxai.yaml
name: shop-feature-x
agent: claude
profiles: [kotlin-spring, react]
branch: feature/x
base: main
repos:
  - path: ../../shop-backend
  - path: ../../shop-frontend
    base: develop
  - url: git@gitlab.com:team/shared-lib.git
secrets: ./secrets.yaml
network:
  allow: ["nexus.firma.de:443"]

Start with boxai up --config examples/boxai.yaml.

Fields

FieldMeaning
nameName of the workspace and the sandbox
agentclaude, copilot or (experimental) antigravity
profilesStack profiles, kombinierbar: kotlin-spring, react
branch / baseFeature branch of the worktrees and the starting branch; base can be overridden per repo
reposLocal repos via path or remote repos via url
secretsPath to a secrets file
network.allowAdditional host allowances for the sandbox

Stack profiles

Profiles provide the image choice and configuration files. In addition, every sandbox allows github.com, api.github.com, gitlab.com and **.amazonaws.com.

Secrets

The secrets file points to sources, never to embedded values. References in YAML are ${env:NAME} and ${file:path}. Template: boxai init generates secrets.example.yaml.

The sandbox only sees a placeholder, which the sbx proxy replaces in requests to the allowed hosts. That is why hosts is required, and boxai also allows every secret host on the network.

Fallback secrets.mode: env

For tools where placeholders fail (such as AWS SigV4), boxai passes the real values via environment variable. The sandbox then sees the plaintext, and boxai warns accordingly.
